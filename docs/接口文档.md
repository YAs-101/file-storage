# 文件存储服务 · 接口文档（M1）

> 适用版本：M1（上传 / 下载 / 删除 / 断点续传四条链路闭环）
> 更新日期：2026-10-24
> 服务地址：`http://localhost:8080`

---

## 一、通用约定

### 1.1 身份

用户体系尚未接入，暂用请求头 `X-User-Id` 代替，缺省为 `1`。接入真实鉴权后只需替换这一层，Service 无需改动。

| 约束 | 说明 |
| :--- | :--- |
| 取值 | 正整数。`0` 或负数在 `init` 阶段返回 `403`，其余接口按"无此用户的数据"处理 |
| 越权 | 访问他人文件一律返回 `404` 而非 `403`。`403` 等于确认该 ID 存在，配合自增 ID 可枚举他人文件数量与上传节奏 |

### 1.2 响应包装

除下载接口外，所有接口返回 HTTP `200`，结果放在 body 里：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

| 字段 | 说明 |
| :--- | :--- |
| `code` | `0` 成功，其余为失败。**判断成功只看 `code === 0`** |
| `msg` | 失败原因，可直接展示或作为日志 |
| `data` | 成功时的载荷，失败时为 `null` |

**为什么失败也返回 HTTP 200**：前端只需一套 `code` 分支判断，不必同时处理 HTTP 层与业务层两套错误路径。代价是 HTTP 状态码不能反映成败，所以必须有本文档。

**唯一例外是下载接口**，见 [2.6](#26-下载)。

### 1.3 请求链路标识

每个响应都带 `X-Request-Id` 头。

- 客户端可自带该头，服务端会透传（便于跨服务串联），但只接受 `[A-Za-z0-9_-]{1,64}`，不合法则重新生成。
- 服务端日志每行形如 `18:27:20.734 INFO [099ed4e5] [nio-8080-exec-9] UploadServiceImpl : ...`，方括号内即该 ID。
- 报障时提供这个 ID 即可定位一次上传的全部请求。

### 1.4 关键常量

| 参数 | 值 | 位置 | 说明 |
| :--- | :--- | :--- | :--- |
| 分片大小 | 5 MB（5242880 字节） | `storage.chunk-size` | 由**服务端**决定，与 S3 multipart 下限一致 |
| 单文件上限 | 5 GB（5368709120 字节） | `storage.max-file-size` | 超过返回 `1009` |
| 会话有效期 | 24 小时 | `storage.session-expire-hours` | 过期后不可续传，需重新 `init` |
| 合并锁 TTL | 30 秒 | `storage.merge-lock-seconds` | 只影响并发合并的失败速度，不影响正确性 |
| 列表单页上限 | 200 | 代码常量 | 超过按 200 处理 |

> **分片大小必须用 `init` 返回值**。客户端在请求里传 `chunkSize` 会被用于一致性校验：与服务端一致则忽略，不一致直接返回 `1004`，避免"按自己的分片切片、直到最后一个分片才失败"。

### 1.5 错误码

| code | 含义 | 典型触发 |
| :--- | :--- | :--- |
| `0` | 成功 | — |
| `400` | 参数错误 | 字段缺失、格式非法、JSON 不合法、路径变量类型错 |
| `401` | 未认证 | 预留 |
| `403` | 无权限 | `X-User-Id` 非正整数；操作他人上传会话 |
| `404` | 资源不存在 | 文件不存在、接口路径不存在、越权访问 |
| `405` | 请求方法不支持 | 用 GET 调 `POST` 接口 |
| `409` | 状态冲突 | 预留 |
| `413` | 请求体过大 | 单个分片超过容器上限 |
| `500` | 服务器内部错误 | 未预期异常、数据库不可用 |
| `1001` | 上传会话不存在 | `uploadId` 格式合法但库里没有 |
| `1002` | 会话状态不允许此操作 | 对已完成/已取消/已失败的会话继续上传 |
| `1003` | 分片不完整 | 分片数量或序号不连续就调 `complete` |
| `1004` | 分片序号或大小不符 | 序号越界、分片字节数不对、声明的 `chunkSize` 与服务端不一致 |
| `1005` | 正在合并中 | 并发调 `complete`，本次未抢到合并权 |
| `1006` | 合并后 MD5 与声明不一致 | 上传过程中内容被改动 |
| `1007` | 上传会话已过期 | 超过 24 小时 |
| `1008` | 存储层操作失败 | 磁盘不可读、对象丢失 |
| `1009` | 文件超过大小上限 | `fileSize` > 5 GB |
| `1010` | 数据所属存储后端不可用 | 记录声明的后端未注册、或连接配置缺失导致装配失败。与 `404` 的区别：文件确实存在，只是本进程连不上它所在的后端 |

## 二、接口清单

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/health` | 健康检查 |
| POST | `/api/upload/init` | 初始化上传 / 秒传判定 / 断点续传查询 |
| PUT | `/api/upload/{uploadId}/chunk/{chunkIndex}` | 上传单个分片 |
| POST | `/api/upload/{uploadId}/complete` | 合并分片 |

| GET | `/api/file/{userFileId}` | 单个文件元信息 |

| DELETE | `/api/file/{userFileId}` | 删除文件 |

### 2.1 健康检查

```
GET /api/health
```

**成功**

```json
{ "code": 0, "msg": "ok", "data": { "status": "UP", "app": "file-storage", "time": "2026-10-24T18:27:07.24" } }
```

无失败分支。仅表示进程可服务，不检测 MySQL / Redis 连通性。

### 2.2 初始化上传

```
POST /api/upload/init
Content-Type: application/json
X-User-Id: 1
```

**请求体**

| 字段 | 类型 | 必填 | 约束 |
| :--- | :--- | :--- | :--- |
| `fileName` | string | 是 | 1~255 字符；不得含 `/ \ : * ? " < > |` 或控制字符 |
| `fileSize` | long | 是 | > 0 且 ≤ 5 GB |
| `fileMd5` | string | 是 | 32 位十六进制，整文件 MD5 |
| `contentType` | string | 否 | ≤ 128 字符 |
| `chunkSize` | long | 否 | 传了就必须等于服务端的 5242880，否则 `1004` |

**成功（需上传）**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "uploadId": "6f724ab19c1444db84948d18d811e770",
    "instant": false,
    "chunkSize": 5242880,
    "chunkTotal": 3,
    "uploaded": [],
    "fileId": null,
    "userFileId": null
  }
}
```

**成功（秒传命中）**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "uploadId": null,
    "instant": true,
    "chunkSize": 5242880,
    "chunkTotal": 3,
    "uploaded": [],
    "fileId": 30,
    "userFileId": 40
  }
}
```

`instant=true` 时文件已可用，**不要再传分片、不要再调 `complete`**。`uploadId` 为 `null`。

**断点续传**：同一用户重复 `init` 相同 `fileMd5 + fileSize` 且会话未过期，返回**同一个 `uploadId`**，`uploaded` 列出已收到的分片序号，客户端只补缺失部分。

**失败**

| code | 触发条件 |
| :--- | :--- |
| `400` | 请求体非 JSON；必填字段缺失；`fileName` 含非法字符；`fileMd5` 非 32 位十六进制；`fileSize` ≤ 0 |
| `403` | `X-User-Id` 为 0 或负数 |
| `1004` | 传入的 `chunkSize` 与服务端配置不一致 |
| `1009` | `fileSize` 超过 5 GB |

### 2.3 上传分片

```
PUT /api/upload/{uploadId}/chunk/{chunkIndex}
Content-Type: application/octet-stream
X-User-Id: 1
X-Chunk-Md5: <可选，该分片的 MD5>
```

**请求体是原始二进制**，不是 multipart。少一层 boundary 解析，也便于直接把流写进磁盘而不落内存。

| 参数 | 位置 | 约束 |
| :--- | :--- | :--- |
| `uploadId` | path | 32 位小写十六进制，格式不符直接 `400` |
| `chunkIndex` | path | `0 ~ chunkTotal-1`，整数 |
| 分片字节数 | body | 非末片必须等于 `chunkSize`；末片等于 `fileSize - chunkSize*(chunkTotal-1)` |

**成功**

```json
{ "code": 0, "msg": "ok", "data": { "chunkIndex": 0, "received": 5242880, "uploadedCount": 1, "chunkTotal": 2 } }
```

**幂等**：同一分片重复上传直接覆盖，`uploadedCount` 不会重复计数。

**失败**

| code | 触发条件 |
| :--- | :--- |
| `400` | `uploadId` 格式非法；`chunkIndex` 不是数字 |
| `403` | 该会话不属于当前 `X-User-Id` |
| `1001` | 会话不存在 |
| `1002` | 会话已完成合并，或已取消、已失败 |
| `1004` | 序号越界；分片字节数与预期不符；`X-Chunk-Md5` 与实际不符 |
| `1005` | 该会话正在合并，暂停上传 |
| `1007` | 会话已过期 |
| `1008` | 写盘失败 |

> 分片大小不符时**不清除**已写入的脏分片：库里没有这条记录，合并只按库取分片，下次重传同序号会直接覆盖。

---

### 2.4 合并分片

```
POST /api/upload/{uploadId}/complete
Content-Type: application/json
X-User-Id: 1
```

无请求体（或空 `{}`）。

**成功**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "fileId": 30,
    "userFileId": 40,
    "fileMd5": "8577fa43ba071a039f44e95e95098e67",
    "fileSize": 12582912,
    "storedSize": 12582912,
    "reused": false
  }
}
```

| 字段 | 说明 |
| :--- | :--- |
| `storedSize` | 实际落盘字节数，应等于 `fileSize`；不等说明存储层截断 |
| `reused` | `true` 表示此前已合并完成，本次是纯读，没有重复建文件 |

**幂等**：重复调用安全。三层保护——Redis 锁让并发请求快速失败、状态机 CAS 保证只有一次真正合并、`uk(file_md5, file_size)` 唯一索引兜底。

**失败**

| code | 触发条件 | 处理建议 |
| :--- | :--- | :--- |
| `400` | `uploadId` 格式非法 | 检查参数 |
| `403` | 会话不属于当前用户 | 换正确用户 |
| `1001` | 会话不存在 | 重新 `init` |
| `1002` | 会话已取消 / 已失败 / 已过期 | 重新 `init` |
| `1003` | 分片数量不足或序号不连续，`msg` 含总数 | 补齐缺失分片后重试 |
| `1005` | 另一个请求正在合并 | **稍后重试**，不要立刻重试 |
| `1006` | 合并后 MD5 与声明不一致 | 产物已删除，从头重传 |
| `1008` | 合并或校验读写失败 | 重试 |

> 合并失败会把会话状态从"合并中"退回"上传中"，**可以重试**，不会永久卡死。

### 2.5 文件列表

```
GET /api/file/list?limit=50&offset=0
X-User-Id: 1
```

| 参数 | 默认 | 约束 |
| :--- | :--- | :--- |
| `limit` | 50 | 1~200，越界自动夹紧到边界值（不报错） |
| `offset` | 0 | ≥ 0，负数按 0 处理 |

**成功**

```json
{
  "code": 0,
  "msg": "ok",
  "data": [
    { "userFileId": 40, "fileName": "e2e_12m.bin", "fileSize": 12582912,
      "fileMd5": "8577fa43...", "contentType": null, "createdAt": "2026-10-24T18:27:20" }
  ]
}
```

按 `userFileId` 倒序，只返回可用状态的文件。**不返回 `objectKey`**——存储路径属于内部实现，泄露后配合目录遍历会造成风险。

**失败**：仅 `400`（`limit`/`offset` 非数字）。

### 2.6 下载

```
GET /api/file/{userFileId}/download
X-User-Id: 1
Range: bytes=0-1048575            # 可选
If-None-Match: "8577fa43..."      # 可选
```

**这是唯一直接使用 HTTP 语义的接口**，返回体是文件字节流，不是 JSON。消费者是浏览器与下载器，它们只认 HTTP 语义。

| 场景 | HTTP | 响应头 | 响应体 |
| :--- | :--- | :--- | :--- |
| 完整下载 | `200` | `Content-Length`、`ETag`、`Accept-Ranges: bytes`、`Content-Disposition` | 文件字节 |
| 区间下载 | `206` | 上述 + `Content-Range: bytes 0-1048575/12582912` | 该区间字节 |
| `If-None-Match` 命中 | `304` | `ETag` | 空 |
| 区间越界 | `416` | `Content-Range: bytes */12582912` | 空 |
| 文件不存在 / 越权 | `404` | `Content-Type: application/json` | `{"code":404,"msg":"文件不存在"}` |
| 存储层读取失败 | `500` | 同上 | `{"code":1008,...}` |
| 记录所属后端不可用 | `500` | 同上 | `{"code":1010,...}` |
| `Range` 语法非法 | `200` | — | 忽略该头，回退全量 |

**区间支持范围**

- 只支持单区间。`bytes=0-9,20-29` 按 RFC 7233 允许的方式忽略，退化为 `200` 全量。多区间需要 `multipart/byteranges`，客户端几乎不产生这种请求。
- 支持三种写法：`bytes=0-99`、`bytes=1048576-`（到末尾）、`bytes=-100`（末尾 100 字节）。

**断点续传**：客户端用 `206` + `Content-Range` 记录已下载偏移，中断后以 `bytes=<offset>-` 续传；多线程下载器按 `Content-Length` 切段并发请求，各段拼接后 MD5 与列表返回的 `fileMd5` 一致。

**缓存**：`ETag` 直接取整文件 MD5。内容按 MD5 寻址，MD5 不变即内容不变，不需要额外版本号或 `Last-Modified`。

> 出错时返回真实 HTTP 状态码而非 `200`，因为浏览器拿到 `200` 就认为下载成功，会把错误 JSON 存成一个"文件"。

### 2.8 删除文件

```
DELETE /api/file/{userFileId}
X-User-Id: 1
```

**成功**

```json
{ "code": 0, "msg": "ok", "data": { "userFileId": 40, "alreadyDeleted": false, "objectRemoved": true, "remainingRefs": 0 } }
```

| 字段 | 说明 |
| :--- | :--- |
| `alreadyDeleted` | `true` 表示此前已删，本次无副作用（幂等） |
| `objectRemoved` | `true` 表示引用归零，物理对象已删除 |
| `remainingRefs` | 删除后剩余引用数；`alreadyDeleted=true` 时为 `-1`（未知） |

**删的是引用，不是数据**：同一内容的多个用户文件共享一份物理对象，只有最后一个引用释放时才删对象。A 删除后 B 仍可正常下载。

**失败**

| code | 触发条件 |
| :--- | :--- |
| `400` | `userFileId` 不是数字 |
| `404` | 文件不存在、已删除，或不属于当前用户 |

## 三、典型流程

### 3.1 从零上传

```
1. POST /api/upload/init          → instant=false, uploadId, chunkSize=5242880, chunkTotal
2. PUT  /api/upload/{id}/chunk/0  → 前 chunkTotal-1 片，每片正好 5242880 字节
   PUT  /api/upload/{id}/chunk/N  → 末片，字节数 = fileSize - 5242880*(chunkTotal-1)
3. POST /api/upload/{id}/complete → fileId, userFileId
4. GET  /api/file/{userFileId}/download → 校验 MD5
```

### 3.2 中断后续传

```
1. POST /api/upload/init          → 返回同一 uploadId，uploaded=[0,1,2]
2. PUT  /api/upload/{id}/chunk/3  → 只补缺失分片
3. POST /api/upload/{id}/complete
```

### 3.3 秒传

```
1. POST /api/upload/init          → instant=true, fileId, userFileId
2. 结束。不需要传分片，不需要 complete。
```

### 3.4 并发合并的正确处理

多个客户端同时调 `complete` 时：一个返回 `reused=false`（真正合并），其余可能返回 `1005` 或 `reused=true`。收到 `1005` 应退避 1~2 秒后重试，重试会拿到 `reused=true`。
